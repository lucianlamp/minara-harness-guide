0. はじめに: Grok Bot の VM に入れてみた

手元には、Grok Bot という AI エージェントを動かすための Linux VM が 1 台あります。実体は Debian 13 の Docker コンテナで、X11 デスクトップを VNC 越しに使う構成です。もともと GUI アプリを動かす前提の箱ではありません。そこに「Claude Code の金融版ハーネス」と紹介されていた Minara Harness を同居させたらどうなるか気になり、試してみることにしました。macOS 版を紹介する記事は見かけましたが、Linux 版の画面をひととおり並べた記事は見当たりませんでした。

Linux 用の .deb（1.0.1、711 MB）を入れて Minara を起動すると、ログイン直後に画面が真っ白になって落ちました。原因はコンテナの /dev/shm が 64 MB しかなく、レンダラーが net::ERR_INSUFFICIENT_RESOURCES を出して死んでいたことです。--disable-gpu では直らず、--disable-dev-shm-usage（サンドボックスがない環境なので --no-sandbox も併用）で直りました。詳しい手順は 9 章にまとめています。

この VM のデスクトップは Grok Bot が使っているため、マウスで 1 画面ずつクリックして撮っていくわけにはいきません。そこで Electron の DevTools ポート（Chrome DevTools Protocol）に Python からつなぎ、画面遷移とスクリーンショットの取得をすべてスクリプトにまかせました。この記事はその過程で撮った 40 枚を、画面ごとに整理したものです。1 章から順に見ていきます。

1. Minara Harness とは？「ローカル金融エージェント」と npm CLI の違い

Minara Harness は、手元の PC 上で動くデスクトップアプリ（Electron 製）です。起動すると内部で AI エージェントとローカルゲートウェイが立ち上がり、次の機能を 1 つのウィンドウの中で完結させます。

  • 市場リサーチ・チャット
  • 戦略のバックテストと自動運用（Autopilot）
  • 定時バッチ・監視の自動化
  • 分析ダッシュボードの生成
  • 接続ウォレットのポートフォリオ管理

Claude Code がコード生成のための実行基盤（ハーネス）であるのに対し、Minara Harness は市場調査から注文執行までを担う金融特化のエージェント基盤といえます。

混同しやすいのが、同じ Minara が提供する npm パッケージの minara CLI です。こちらは Minara サーバーへコマンドを送る軽量クライアントで、現物スワップ（18 チェーン）や Hyperliquid の無期限先物（perps）注文を端末から打つためのものです。ログイン情報の保存先も含めて Harness とは別物であり、この記事で扱うのは Harness のみです。

Harness の思考エンジン（モデル）は差し替えられます。標準は Minara 独自モデル（auto）ですが、設定で ChatGPT アカウントを OAuth 連携すると、GPT 6 Astra を含む OpenAI 系のモデルがチャットの選択肢に加わります（手順は 3 章）。Anthropic や OpenRouter の API キーも設定可能です。

3. 最初に触る 3 画面: Office、Chat、そしてモデルを GPT 6 Astra に切り替える手順

3-1. Chat は質問カテゴリを選ぶところから始めるのが早道

Office とは別に Chat という画面があります。Office が作業全般の入口であるのに対し、Chat は市場についての問答に特化しており、Trending / Stock / Pre-IPO / Crypto / Macro / Sentiment / Learn のカテゴリごとに質問のプリセットが用意されています。「$ETH を動かしている一番もっともらしいシナリオは？」といった質問が 8 ページ分あり、クリックするだけで投げられます。

3-2. モデルの切り替え手順（入力欄右下から 3 ステップで変更）

ChatGPT アカウントを連携済みなら（連携手順は 7 章の Provider & Model）、チャットの入力欄右下に「GPT 5.6 Terra · Medium」の形式でモデル名と推論強度が常時表示されます。ここが切り替えの入口です。

  1. 右下のモデル名（例: 「GPT 5.6 Terra · Medium」）をクリックする。Output / Reasoning / Model の 3 項目のメニューが開く
  2. 「Model」にカーソルを合わせる。左側にモデル一覧が展開する
  3. 一覧の先頭にある「GPT 6 Astra（gpt-6-astra）」を選択する
一覧に並ぶモデルは連携中のプロバイダに依存します。ChatGPT を連携していない状態では「Minara Agent」のみが表示される仕様と考えられます（※未連携時の画面は未キャプチャのため推定）。Office、Strategy Studio、Automations、Data Studio の入力欄にも同じセレクタがあり、機能ごとに別のモデルを割り当てられます。

4. Strategies: 戦略を作る・探す・走らせる（Autopilot）

Harness の中心機能です。上部に Dashboard / Strategy Studio / Top Strategies / Marketplace の 4 タブがあり、「作る（Studio）→ 探す（Top / Marketplace）→ 走らせる（Dashboard の Autopilot）」の順に見ていくと全体の構造がつかめます。

4-1. Autopilot の基本設計: 専用ウォレット 1 つに戦略 1 つ、投資上限とドローダウン停止を先に決める

4-2. Dashboard は自分の作者ページ。稼働状況は内側の Autopilot タブで確認

Dashboard タブを開くと、まず自分の作者カード（アイコン、公開戦略数、Get Verified ボタン）が表示されます。その下に Welcome / Autopilot / My Strategies / Starred の内側タブがあり、稼働中の戦略を確認するのは Autopilot タブです。

My Strategies には自作の戦略が並びます。今回の環境では BTCUSDT の下書きが 2 本（Wider Stop Revert、RSI Stoch Snapback）あり、どちらもバックテスト前の Draft 状態です。Starred は他人の戦略のブックマークで、購読前の比較に使います。

4-3. Strategy Studio: 「文章 → コード → バックテスト → 本番」を 1 画面で回す

戦略を作成する画面です。ツアーの例文は「Buy BTC when hourly RSI falls below 30; sell above 70.」で、これを Describe 欄に入力するとエージェントが売買ルールをコード化し、バックテストまで進めます。時系列（Time-series: 1 銘柄の売買タイミングを扱う）とクロスセクション（Cross-sectional: 複数銘柄の相対評価を扱う）の 2 種類があり、Factor library から既製のファクターも参照できます。

4-4. Top Strategies と Marketplace: 「購読可」と「認証作者」で絞り込んで探す

Top Strategies は 90 日ローリングの累積リターンでランキングする画面で、Consistent（安定型）と Aggressive（攻撃型）に分かれます。右側の Popular Creators には Minara Labs（フォロワー 2.6K）、MrTokenAI（1.7K）などの作者が並びます。Marketplace は購読して自分のウォレットで走らせられる戦略の一覧で、カードの「Run」を押すと 4-1 の Autopilot 設定に進みます。

Marketplace の年率はバックテストと実運用が混ざった値で、画面上では区別がつきません。4-2 の実稼働例では、Starred で年率 +3608% と表示されていた戦略が、9 日間の実績では +8.23% でした。数字を鵜呑みにせず、投資上限とドローダウン停止を必ず設定してから Run してください。

5. Automations: 定時レビューや監視を文章で組む

「毎朝ポートフォリオを確認して要約を送って」といった依頼を、トリガー（時刻や条件）→ 処理 → 通知という自動化フローに変換する画面です。ツアーの例文は「Review my watchlist before the market opens and send me a summary.」で、これが「01 Start on time / 02 Review watchlist / 03 Send summary」の 3 段階に分解されます。通知先は 7 章の Messaging で Telegram、Discord、Lark を連携しておきます。

今回の環境ではまだ自動化を作成していないため、実行結果の画面はありません。バックグラウンドで PC を操作させたい場合は、7 章の Computer control で「Allow background tasks to control this computer」を有効にする必要があります。

6. More 配下の機能: Portfolio、Markets、Data Studio、Coding

6-1. Portfolio: 現物とパーペチュアルのウォレットを 1 画面に集約

6-4. Coding: フォルダを渡してコードを書かせる画面。Git 権限は設定で細かく制御

8. 公式資料で見る Minara Harness（ベンチマーク・Institution・Trading memory）

ここからの 3 枚は、この記事の他の画像とは出どころが異なります。Minara の公式ベンチマーク資料と、macOS 版の紹介画像です。手元の Linux 1.0.1 で撮影した実機スクリーンショットではありません。Linux 版との違いや未検証の部分は、各項目で明記します。

8-1. ベンチマーク: 財務レポートは強いが、AgentDojo や SkillsBench は横並びに近い

Minara は自社のハーネスを OpenClaw、Hermes、Claude Code の 3 つと比較したベンチマーク結果を公開しています。GPT-5.6 Luna Pro、DeepSeek V4 Flash、Qwen 3.7 Flash という 3 つのベースモデルの上に各ハーネスを乗せ、6 種類のベンチマークで採点する形式です。

公式ベンチマークが強調しているのは「財務レポートに強い」という 1 点です。それ以外のベンチマークは他フレームワークと拮抗しているか、ベースモデルによって順位が入れ替わります。数字を見る際は、どのベンチマークの話かを確認したうえで受け取るのが安全です。

8-2. Institution モード: 13 エージェントの Roundtable（未検証・Mac 版）

3 章で触れた Chat の Institution セッションについて、今回の Linux 1.0.1 環境ではセッションを作成しておらず未検証のままです。macOS 版の公式画像には、Institution を開いたときの様子が写っています。

右ペインには「Roundtable — Full-Spectrum Review（Built-in）」として、合計 13 エージェントが 7 段階に分かれて動作する様子が表示されています。

  1. Retrospective（Context setup、1 エージェント）
  2. Parallel Research（Independent parallel、4 エージェント）
  3. Thesis Debate（Cross-review、2 エージェント）
  4. Research Synthesis（Managed synthesis、1 エージェント）
  5. Execution Plan（Managed synthesis、1 エージェント）
  6. Risk Review（Cross-review、3 エージェント）
  7. Decision Committee（Final convergence、1 エージェント）

公式の説明を訳すと、「あなたの研究に AI エージェントのチームを配置する。専門家が機会を調査し、想定を検証し、リスクをレビューする。情報源や意見の相違を追跡し、証拠が最終報告書をどう形作るかを確認できる」というものです。実際に Linux 1.0.1 で Institution セッションを作成し、Roundtable を最後まで走らせた記録はまだないため、この 7 段階が Linux 版でも同じ構成で表示されるかは今回確認できていません。

8-3. Trading memory & learning: Mac 版のパーソナライズ設定は Linux 1.0.1 にはまだない

7 章で見た Linux 1.0.1 の設定は General から Updates まで 10 項目で、パーソナライズ専用のカテゴリは含まれていません。macOS 版の公式画像には、Personalization の中に「Trading memory & learning」という項目があり、Linux 版より一歩先を行く画面に見えます。

Linux 1.0.1 側で近い役割を持つのは、7-5 で紹介した Data → Workspace の SOUL.md、AGENTS.md、USER.md、MEMORY.md です。こちらはエージェントの視点や行動指針をテキストファイルとして直接編集する仕組みであり、Mac 版の Trading memory のように「学習した内容を項目ごとに一覧で見る」画面ではありません。同じ「記憶と学習」という役割を、Linux 版はファイル編集で、Mac 版は専用の設定画面で扱っているという違いです。

9. Linux（Docker）で動かすときの注意点

.deb をインストールすると /opt/Minara/Minara が本体で、/usr/bin/Minara にリンクが張られます（npm の minara とは大文字小文字で区別されるため衝突しません）。通常の Linux デスクトップであればメニューから起動するだけで済みますが、Docker コンテナ内で動かした今回は 2 つの問題に遭遇しました。

1 つ目はログイン直後に画面が真っ白になる症状です。コンテナの /dev/shm が 64 MB しかなく、レンダラーが JS のチャンクを読み込む途中で net::ERR_INSUFFICIENT_RESOURCES を出して落ちていました。--disable-gpu では解決せず、--disable-dev-shm-usage で解決します。2 つ目はサンドボックス用のユーザー名前空間がない環境で、--no-sandbox が必要です。この 2 つを加えた起動スクリプトは次のとおりです。

#!/usr/bin/env bash
export DISPLAY="${DISPLAY:-:0}"
exec /opt/Minara/Minara --no-sandbox --disable-dev-shm-usage "$@"

ホスト上の通常のデスクトップ Linux でこの 2 つの起動オプションが必要かどうかは未検証です（※/dev/shm が数 GB ある通常環境では不要と考えられます）。もう 1 点、Linux 版 1.0.1 では More メニューの Factor Research が灰色表示で開けません。macOS 版の紹介記事にある機能が見当たらないときは、まずここを疑ってください。

1. Minara Harness は「ローカルで動く金融エージェント」で、npm の CLI とは別物

Minara Harness は、手元の PC で動くデスクトップアプリ（Electron 製）です。起動すると内部に AI エージェントとローカルのゲートウェイが立ち上がり、チャット、戦略のバックテストと自動売買（Autopilot）、定時実行の自動化、ダッシュボード生成、ポートフォリオ管理を 1 つの窓の中でこなします。Claude Code が「コードを書くためのエージェントの器（ハーネス）」だとすれば、Minara Harness は「市場を調べて売買するためのエージェントの器」です。

混同しやすいのが、同じ Minara が出している npm パッケージの minara CLI です。こちらは Minara のサーバーに命令を投げる薄いクライアントで、現物スワップ（18 チェーン）や Hyperliquid の perps 注文を端末から打つためのものです。Harness とはログイン情報も別に保存されます。この記事で扱うのは Harness のほうだけです。

Harness の頭脳は差し替えられます。標準は Minara 自身のモデル（auto）ですが、設定で ChatGPT アカウントを OAuth 接続すると、GPT 6 Astra を含む OpenAI 系のモデルがチャットの選択肢に並びます（3 章で手順を示します）。Anthropic や OpenRouter の API キーも受け付けます。

2. 画面の地図: メインメニュー 6 つ、More の中に 4 つ、設定に 12 項目

起動直後の画面が Office です。左ペインに Office / Chat / Coding / Strategies / Automations / More の 6 項目が並び、Portfolio と Markets は More の中に隠れています。macOS 版の紹介記事とはメニューの並びが違うので、先に全体の地図を押さえておきます。

3. 最初に触る 3 画面: Office、Chat、そしてモデルを GPT 6 Astra に切り替える

3-1. Chat は「質問カテゴリを選んでクリック」から始めるのが早い

Office とは別に Chat という画面があります。Office が作業の入口なのに対して、Chat は市場についての問答に特化していて、Trending / Stock / Pre-IPO / Crypto / Macro / Sentiment / Learn のカテゴリごとに質問のプリセットが用意されています。「$ETH を動かしている一番もっともらしいシナリオは？」といった質問が 8 ページ分あり、クリックするだけで投げられます。

3-2. モデルの切り替えは入力欄の右下から。GPT 6 Astra は 3 クリック

ChatGPT アカウントを接続していれば（接続手順は 7 章の Provider & Model）、チャットの入力欄右下に「GPT 5.6 Terra · Medium」のようにモデル名と推論強度が表示されます。ここが切り替えの入口です。

  1. 入力欄右下の「GPT 5.6 Terra · Medium」をクリックする。Output / Reasoning / Model の 3 行のメニューが開く
  2. 「Model」の行にカーソルを合わせる。左にモデル一覧が出る
  3. 一覧の先頭にある「GPT 6 Astra（gpt-6-astra）」をクリックする
一覧に並ぶモデルは、接続したプロバイダで決まります。ChatGPT を接続していない状態では「Minara Agent」だけになる見込みです（推定: 接続前の一覧は撮っていません）。Office、Strategy Studio、Automations、Data Studio の入力欄にも同じセレクタがあり、画面ごとに別のモデルを選べます。

4. Strategies: 戦略を作る・探す・走らせる（Autopilot）

Harness の中心機能です。上部に Dashboard / Strategy Studio / Top Strategies / Marketplace の 4 タブがあり、「作る（Studio）→ 探す（Top / Marketplace）→ 走らせる（Dashboard の Autopilot）」の順に読むと構造がつかめます。

4-1. Autopilot の考え方: 専用ウォレット 1 つに戦略 1 つ、投資上限とドローダウン停止を先に決める

4-2. Dashboard は自分の作者ページ。稼働状況は内側の Autopilot タブ

Dashboard タブを開くと、まず自分の作者カード（アイコン、公開戦略数、Get Verified ボタン）が出ます。その下に Welcome / Autopilot / My Strategies / Starred の内側タブがあり、稼働中の戦略を見るのは Autopilot タブです。

My Strategies には自作の戦略が並びます。今回の環境では BTCUSDT の下書きが 2 本（Wider Stop Revert、RSI Stoch Snapback）で、どちらもまだバックテスト前の Draft 状態です。Starred は他人の戦略のブックマークで、購読前の比較に使います。

4-3. Strategy Studio は「文章 → コード → バックテスト → 本番」を 1 画面で回す

戦略を作る画面です。ツアーの例文は「Buy BTC when hourly RSI falls below 30; sell above 70.」で、これを Describe 欄に書くとエージェントが売買ルールをコードにし、バックテストまで進めます。時系列（Time-series: 1 銘柄の売買タイミング）とクロスセクション（Cross-sectional: 複数銘柄の相対評価）の 2 種類があり、Factor library から既製のファクターも引けます。

4-4. Top Strategies と Marketplace: 探すときは「購読可」と「認証作者」で絞る

Top Strategies は 90 日ローリングの累積リターンでランキングする画面で、Consistent（安定型）と Aggressive（攻撃型）に分かれます。右側の Popular Creators には Minara Labs（フォロワー 2.6K）、MrTokenAI（1.7K）などの作者が並びます。Marketplace は購読して自分のウォレットで走らせられる戦略の一覧で、カードの「Run」を押すと 4-1 の Autopilot 設定に進みます。

Marketplace の年率はバックテストと実運用が混ざった値で、画面上では区別がつきません。4-2 の実稼働では、Starred で年率 +3608% と表示されていた戦略が 9 日間で +8.23% でした。数字を鵜呑みにせず、投資上限とドローダウン停止を必ず設定してから Run してください。

5. Automations: 定時レビューや監視を文章で組む

「毎朝ポートフォリオを確認して要約を送って」のような依頼を、トリガー（時刻や条件）→ 処理 → 通知の自動化に変える画面です。ツアーの例は「Review my watchlist before the market opens and send me a summary.」で、これが「01 Start on time / 02 Review watchlist / 03 Send summary」の 3 段に分解されます。通知先は 7 章の Messaging で Telegram、Discord、Lark を接続しておきます。

今回の環境ではまだ自動化を作っていないため、実行結果の画面はありません。バックグラウンドで PC を操作させたい場合は、7 章の Computer control で「Allow background tasks to control this computer」を有効にする必要があります。

6. More の中身: Portfolio、Markets、Data Studio、そして Coding

6-1. Portfolio は現物とパーペチュアルのウォレットを 1 画面に束ねる

接続した全ウォレットの合計額と内訳です。今回の環境は 4 ウォレットで合計 $6,118.22。現物（Spot）は EVM と Solana のアドレスを持つ 1 ウォレットに 3 資産で $522.88、パーペチュアル用は Hyperliquid が 2 つと Lighter が 1 つで合計 $5,595.34。稼働中の Autopilot はウォレットの行に「Autopilot · Running」として表示され、クリックで 4-2 の画面に飛びます。

6-2. Markets は指数とセクターの俯瞰。Crypto とウォッチリストはタブ切替

6-3. Data Studio は「見たいものを書く → 表示 → 会話で直す」でダッシュボードを作る

6-4. Coding はフォルダを渡してコードを書かせる画面。Git の権限は設定で細かく絞れる

8. 公式資料で見る Minara Harness（ベンチマーク・Institution・Trading Memory）

ここから 3 枚は、この記事の他の画像とは出どころが違います。Minara の公式ベンチマーク資料と、macOS 版の紹介画像です。手元の Linux 1.0.1 で撮った実機スクリーンショットではありません。Linux 版との違いや未検証の部分は、各項目で明記します。

8-1. ベンチマーク: 財務レポートは強いが、AgentDojo や SkillsBench は横並びに近い

Minara は自社のハーネスを OpenClaw、Hermes、Claude Code の 3 つと比較したベンチマーク結果を公開しています。GPT-5.6 Luna Pro、DeepSeek V4 Flash、Qwen 3.7 Flash という 3 つのベースモデルの上に各ハーネスを乗せ、6 種類のベンチマークで採点する形式です。

公式ベンチマークが強調しているのは「財務レポートに強い」という 1 点です。それ以外のベンチマークは他フレームワークと拮抗しているか、ベースモデルによって順位が入れ替わります。数字を見るときは、どのベンチマークの話かを確認したうえで受け取るのが安全です。

8-2. Institution モード: 13 エージェントの Roundtable（未検証・Mac 版）

3 章で触れた Chat の Institution セッションについて、今回の Linux 1.0.1 環境ではセッションを作らず未検証のままでした。macOS 版の公式画像には、Institution を開いたときの様子が写っています。

右ペインには「Roundtable — Full-Spectrum Review（Built-in）」として、合計 13 エージェントが 7 段階に分かれて動く様子が表示されています。

  1. Retrospective（Context setup、1 エージェント）
  2. Parallel Research（Independent parallel、4 エージェント）
  3. Thesis Debate（Cross-review、2 エージェント）
  4. Research Synthesis（Managed synthesis、1 エージェント）
  5. Execution Plan（Managed synthesis、1 エージェント）
  6. Risk Review（Cross-review、3 エージェント）
  7. Decision Committee（Final convergence、1 エージェント）

公式の説明を訳すと、「あなたの研究に AI エージェントのチームを配置する。専門家が機会を調査し、想定を検証し、リスクをレビューする。情報源や意見の相違を追跡し、証拠が最終報告書をどう形作るかを確認できる」というものです。実際に Linux 1.0.1 で Institution セッションを作って Roundtable を最後まで走らせた記録はまだないため、この 7 段階が Linux 版でも同じ構成で出るかは今回は確認できていません。

8-3. Trading memory & learning: Mac 版のパーソナライズ設定は Linux 1.0.1 にはまだない

7 章で見た Linux 1.0.1 の設定は General から Updates まで 10 項目で、パーソナライズ専用のカテゴリは含まれていません。macOS 版の公式画像には、Personalization の中に「Trading memory & learning」という項目があり、Linux 版より一歩先に進んだ画面に見えます。

Linux 1.0.1 側で近い役割を持つのは、7-5 で紹介した Data → Workspace の SOUL.md、AGENTS.md、USER.md、MEMORY.md です。こちらはエージェントの視点や行動指針をテキストファイルとして直接編集する仕組みで、Mac 版の Trading memory のように「学習した内容を項目ごとに一覧で見る」画面ではありません。同じ「記憶と学習」という役割を、Linux 版はファイル編集で、Mac 版は専用の設定画面で扱っている、という違いです。

9. Linux（Docker）で動かすときの罠

.deb をインストールすると /opt/Minara/Minara が本体で、/usr/bin/Minara にリンクが張られます（npm の minara とは大文字小文字で区別されるので衝突しません）。普通の Linux デスクトップならメニューから起動して終わりですが、Docker コンテナの中で動かした今回は 2 つの罠を踏みました。

1 つ目は ログイン直後に画面が真っ白になる症状です。コンテナの /dev/shm が 64 MB しかなく、レンダラーが JS のチャンクを読み込む途中で net::ERR_INSUFFICIENT_RESOURCES を出して落ちていました。--disable-gpu では直らず、--disable-dev-shm-usage で解決します。2 つ目はサンドボックス用のユーザー名前空間がない環境で、--no-sandbox が要ります。この 2 つを入れた起動スクリプトはこうなります。

#!/usr/bin/env bash
export DISPLAY="${DISPLAY:-:0}"
exec /opt/Minara/Minara --no-sandbox --disable-dev-shm-usage "$@"

ホスト上の通常のデスクトップ Linux でこの 2 つが必要かは試していません（推定: /dev/shm が数 GB ある通常環境では不要）。もう 1 つ、Linux 版 1.0.1 では More メニューの Factor Research が灰色で開けません。macOS 版の紹介記事にある機能が見当たらないときは、まずここを疑ってください。
